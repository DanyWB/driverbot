# Этап 2. Новая схема данных и базовые модели

Дата закрытия: 2026-07-21.

Статус: выполнен.

## 1. Результат

Laravel содержит новую предметную схему для клиентов, техники, тарифов,
бронирований, доступности и служебной инфраструктуры. Legacy-таблицы и данные бота
на этом этапе не импортировались и не изменялись.

Добавлены группы данных:

- `admin_users` с ролью, признаком активности и временем последнего входа;
- `customers`, контакты и внешние identities без обязательной привязки к Telegram;
- категории, техника, фотографии, сезоны и тарифные уровни;
- бронирования, версии расчета цены и история статусов;
- единый календарь занятости и приватные документы клиентов;
- audit log, notification outbox, service API clients и idempotency keys.

## 2. Ключевые инварианты

- Telegram является одним из источников/identities, но не обязательной частью
  клиента или бронирования.
- Источник `website` предусмотрен заранее для будущего клиентского сайта.
- Даты аренды включительные: `ends_on` не может быть раньше `starts_on`.
- `pending`, `approved` и `active` являются блокирующими статусами на уровне
  доменного enum.
- Занятость хранится отдельно в `vehicle_occupancies`.
- PostgreSQL exclusion constraint запрещает пересекающиеся блокирующие интервалы
  одной техники даже при конкурентных запросах.
- Соседние интервалы разрешены: аренда после `ends_on` начинается со следующего дня.
- Price snapshots, status history и audit logs нельзя изменять через Eloquent после
  создания.
- Внутренние заметки клиентов, пути документов и хеши service tokens скрыты из
  стандартной сериализации.
- Неактивный администратор не может войти по паролю.
- Предсказуемый seed-пользователь удален; администратор создается только командой
  `php artisan admin:create`.

## 3. Типизированный домен

Добавлены PHP enums для:

- booking status и booking source;
- pricing season и pricing tier;
- vehicle type и occupancy type;
- customer contact/identity type;
- actor type.

Тарифный enum однозначно выбирает уровень по полной длительности:

- 1-6 дней: `1d`;
- 7-13 дней: `7d`;
- 14-20 дней: `14d`;
- 21-29 дней: `21d`;
- 30+ дней: `month`.

Seeder создает три сезона и покрывает каждый месяц ровно один раз:

- high: декабрь-март;
- middle: апрель, май, октябрь, ноябрь;
- low: июнь-сентябрь.

## 4. Время и валюта

- системная timezone приложения: `UTC`;
- бизнес-timezone: `Asia/Bangkok`;
- валюта по умолчанию: `THB`;
- даты аренды хранятся как `date`, время выдачи/возврата отдельно и nullable;
- timestamps используют timezone-aware поля.

## 5. Проверки

Выполнено локально на PostgreSQL:

- `migrate:fresh --seed`;
- rollback всех шести миграций этапа и повторный `migrate --seed`;
- реальный конфликт пересекающихся интервалов возвращает PostgreSQL `23P01`;
- соседние и неблокирующие интервалы сохраняются;
- Laravel Pint и PHPStan/Larastan level 7;
- 63 Laravel tests: 61 passed, 2 PostgreSQL-only tests skipped в SQLite-наборе;
- отдельный PostgreSQL-набор: 2 passed.

- state machine и booking actions;
