# Новые условия аренды — передача разработчику

Дата: 14.11.2026. Ветка: `feature/rental-terms-update` (от `origin/origin`, коммит `6792e28`).

Тексты условий согласованы владельцем. В ветке два коммита:

1. `bot: new rental terms with expandable sections` — изменения бота;
2. `docs: rental terms handoff` — этот файл и материалы для сайта.

## 1. Telegram-бот (`bot/`) — готово к выкатке

**Что изменено**

| Файл | Изменение |
|---|---|
| `bot/langs/ru.js`, `ua.js`, `en.js` | Новый текст `conditions_info`: краткая сводка из 6 пунктов и 7 разделов в `<blockquote expandable>` |
| `bot/handlers/conditions.js` | Экран условий показывает только `conditions_info`. Приставка `booking_request_policy` убрана |

**Почему убрана `booking_request_policy`.** Это старый абзац «Заявка рассматривается максимум 48 часов… До подтверждения техника остаётся доступной другим клиентам…». Теперь его заменяет раздел 1 «Как проходит бронирование». Владелец сознательно удалил фразу «техника доступна другим до подтверждения». Ключ оставлен в словарях, чтобы не трогать `check:translations`. Если ключ больше нигде не нужен, его можно удалить отдельно.

**Проверено локально**
- `npm run check:syntax` — ok (162 файла)
- `npm run check:translations` — ok (en, ru, ua; 362 ключа)
- `npm test` — 113/113 pass
- HTML-разметка: только `<b>`, `<i>`, `<blockquote expandable>`, все теги закрыты, `&` экранированы.
- Длина без тегов: RU 2 761, UA 2 770, EN 2 713 символов (лимит Telegram 4 096).
- Тестовые сообщения RU/UA/EN отправлены владельцу через Bot API: Telegram принял все три, разделы раскрываются.

**Как выкатить**
1. Влить `feature/rental-terms-update` в `origin` (PR или merge).
2. Обычный релиз по `OPERATIONS_RUNBOOK.md`: deploy-release и перезапуск `drive-phangan-bot.service`, затем `release:smoke`.
3. Проверить в боте: меню → «📝 Условия аренды», а также экран условий из подтверждения брони. Разделы должны раскрываться по тапу, кнопки «Принять условия» и «Забронировать» работают как раньше.

Миграций нет, переменных окружения нет. Меняются только тексты и одна строка в обработчике.

**Нужен ли `WEBSITE_TERMS_VERSION` / `terms_version`.** В Laravel-режиме бот сохраняет `viewedTermsVersion` из конфигурации. Если принятие условий должно сброситься у всех из-за новых условий (предоплата не возвращается, сбор 300 ฿ за досрочный возврат), поднимите версию условий в конфигурации backend. Решение за владельцем.

## 2. Сайт — страница `/{locale}/policies/terms`

На превью сейчас заглушка «TEST PREVIEW ONLY».

| Файл | Что это |
|---|---|
| `docs/rental-terms/drive-phangan-rental-terms.html` | Готовая вёрстка: EN · RU · UK · TH, все 7 разделов, аккордеоны `<details>` без JS. В начале файла есть короткая инструкция |
| `docs/rental-terms/site-rental-terms.md` | Тексты EN/RU и подробные шаги встраивания (п. 1–10) |

Коротко:
1. CSS между `COPY FROM HERE` и `COPY TO HERE` — в стили сайта. Все цвета и шрифты задаются переменными `--tp-*` на `.tp`.
2. Каждый язык — отдельный Blade-partial, рендерится вместо текущего текста из `config('website.policies.terms.{locale}')`.
3. Шрифты: Anton, Manrope, Noto Sans Thai (для тайского).
4. Тайский: добавить `th` в `config('website.locales')` и в переключатель языков. Перевод сделан без носителя языка, его стоит проверить.
5. Кнопка «Посмотреть договор аренды» сейчас ведёт на `#rental-agreement`, ссылку на договор (PDF или страницу) даст владелец.
6. Владелец может прислать CSS с другой темой. Его делают в панели «Дизайн» в превью (кнопка «Скопировать CSS»). Блок нужно вставить после стилей страницы.
