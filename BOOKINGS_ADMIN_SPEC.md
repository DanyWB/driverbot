# Bookings Admin Spec

Дата: 2026-07-21.

## Цель

Описать, как web-админка заменяет текущий Excel-лист бронирований `2025-2026`.

Старые брони из Excel не импортируются как боевые данные. Лист используется как
референс рабочего процесса: админ смотрит занятость техники по датам, быстро находит
свободный транспорт и фиксирует бронь.

## Что есть в Excel

Лист `2025-2026` устроен как визуальная шахматка:

- строки - техника;
- колонки - календарные дни;
- цветной merged-блок - бронь или занятость;
- текст блока - имя клиента или внутренняя заметка;
- цвета используются как визуальные категории;
- комментарии в основном относятся к технике, а не к конкретной брони.

В Excel нет нормализованных полей для брони:

- телефон;
- Telegram;
- статус;
- цена;
- документы;
- точная история действий;
- отдельное поле предоплаты.

Поэтому в новой админке нельзя просто скопировать Excel. Нужно сохранить его сильную
сторону - визуальную занятость, но добавить нормальные данные и действия.

## Основные экраны

### 1. Timeline / шахматка занятости

Это обязательный экран первого production-релиза.

Назначение:

- заменить визуальную часть Excel;
- быстро смотреть свободные окна;
- принимать брони по телефону/личным сообщениям;
- открывать карточку брони кликом по блоку.

Структура:

- слева список техники;
- сверху календарные дни;
- в ячейках/полосах отображаются брони;
- период по умолчанию - месяц;
- можно переключать месяц или выбирать диапазон дат.

Фильтры:

- тип транспорта: scooter/bike/car;
- категория;
- конкретная техника;
- статус брони;
- активная/скрытая техника;
- только доступная техника на выбранные даты.

Клик по занятому блоку:

- открывает карточку брони.

Клик по свободному месту:

- может открывать форму создания брони с предзаполненной техникой и датой;
- если это сложно на первом этапе, должна быть отдельная кнопка "Создать бронь".

Drag-and-drop:

- не обязателен в первом релизе;
- изменение дат выполняется через карточку брони, чтобы не обойти проверку
  доступности и пересчет цены.

## Цвета и статусы

Цвета Excel нужно перевести в понятные системные категории.

Базовый маппинг:

```text
free -> свободно
pending -> заявка ожидает решения
approved -> бронь подтверждена
active -> аренда началась
completed -> аренда завершена
cancelled -> отменено
cancelled_by_client -> отменено клиентом
expired -> заявка истекла
no_show -> клиент не приехал
maintenance -> ремонт/служебная блокировка
```

Важно:

- не хранить произвольный цвет как бизнес-статус;
- цвет должен быть следствием статуса или категории;
- палитру выбираем сами по статусам.

Рекомендуемая палитра:

- free: светло-серый фон;
- pending: желтый/amber;
- approved: зеленый;
- active: насыщенный green/teal;
- completed: серый;
- cancelled/cancelled_by_client: красный/rose;
- expired: muted gray;
- no_show: темно-красный;
- maintenance/service block: синий или slate.

## 2. Таблица бронирований

Таблица нужна для фильтрации, поиска, экспорта и операционной работы.

Колонки:

- booking ID;
- статус;
- клиент;
- телефон;
- Telegram username;
- источник: bot/admin/phone;
- техника;
- тип техники;
- дата начала;
- дата окончания;
- время выдачи;
- количество дней;
- расчетная цена;
- финальная цена;
- предоплата/депозит заметкой;
- документы: есть/нет;
- комментарий клиента;
- комментарий админа;
- дата создания;
- дата последнего изменения.

Фильтры:

- период;
- статус;
- клиент/телефон;
- техника;
- тип техники;
- источник заявки;
- документы есть/нет;
- активные/архивные.

Действия:

- открыть карточку;
- создать бронь вручную;
- подтвердить pending;
- отменить;
- экспортировать текущую выборку в CSV.

## 3. Ручное создание брони

Обязательно входит в первый production-релиз.

Сценарий:

1. Клиент звонит или пишет вне Telegram.
2. Админ открывает timeline.
3. Админ находит свободную технику.
4. Админ создает бронь вручную.
5. Laravel проверяет доступность и считает цену.
6. Админ сохраняет бронь.

Поля формы:

- существующий клиент или новый клиент;
- имя клиента;
- телефон;
- Telegram username, если есть;
- источник заявки: phone/whatsapp/instagram/telegram/manual;
- техника;
- дата начала;
- дата окончания;
- время выдачи, если известно;
- комментарий клиента;
- внутренняя заметка;
- payment/deposit note;
- расчетная цена;
- финальная цена.

Статус при создании:

- `approved`, если админ уже договорился с клиентом;
- `pending`, если еще нужно уточнение.

После создания:

- техника должна блокироваться на выбранные даты;
- бронь появляется в timeline;
- бронь появляется в таблице;
- расчет цены сохраняется в snapshot.

## 4. Карточка брони

Карточка - основной экран управления одной бронью.

Показывает:

- статус;
- источник;
- клиента;
- контакты;
- технику;
- даты;
- время;
- breakdown цены;
- расчетную цену;
- финальную цену;
- документы;
- комментарии;
- историю действий.

Действия:

- подтвердить;
- изменить даты;
- пересчитать цену;
- вручную изменить финальную цену;
- отменить;
- отметить no-show;
- перевести в active;
- завершить active;
- загрузить документ;
- добавить заметку.

Ограничения:

- no-show только для `approved`;
- `active` нельзя перевести в no-show;
- смена техники внутри брони не входит в первый релиз;
- если нужна другая техника, создается новая бронь.

## 6. Что не переносим из Excel напрямую

Не переносим:

- старые брони как production-данные;
- произвольные merged-ячейки;
- произвольные цвета как бизнес-логику;
- текстовые пометки внутри блока как единственный источник данных.

Переносим:

- логику просмотра занятости;
- визуальные категории через статусы;
- быстрый поиск свободной техники;
- возможность бронировать клиентов, которые не используют Telegram.

## Acceptance Criteria

Экран бронирований считается готовым, когда:

- админ видит timeline по технике и датам;
- админ видит таблицу бронирований;
- админ может создать бронь вручную без Telegram-клиента;
- ручная бронь блокирует технику;
- ручная бронь получает автоматический расчет цены;
- админ может вручную изменить финальную цену;
- клик по блоку timeline открывает карточку брони;
- цвета соответствуют статусам/категориям;
- можно экспортировать брони в CSV;
- старый Excel не нужен для ежедневной операционной работы.
