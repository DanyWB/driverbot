# Этап 7. Техника, фото, цены, клиенты и CSV

Дата закрытия: 2026-07-21.

Статус: выполнен.

## 1. Результат

В Laravel-админке реализованы рабочие разделы управления техникой, категориями,
сезонными тарифами и фотографиями, а также список клиентов, карточка клиента,
приватные документы и экспорт таблицы бронирований в CSV.

Новые экраны доступны только аутентифицированному и подтвержденному администратору:

- `GET /vehicles` - каталог техники с фильтрами и контролем полноты цен;
- `GET /vehicles/{vehicle}/edit` - данные, фото, тарифы и контрольный расчет;
- `GET /categories` - категории техники;
- `GET /customers` и `GET /customers/{customer}` - поиск и история клиента;
- `GET /bookings/export.csv` - экспорт текущей выборки бронирований.

## 2. Техника и категории

Для техники поддержаны создание, просмотр и редактирование. Физическое удаление
намеренно отсутствует: техника выключается через `is_active` и скрывается из
клиентских каналов через `is_visible_for_booking`, поэтому старые брони сохраняют
ссылку и историю.

Основные инварианты:

- неактивная техника всегда скрыта для бронирования;
- опубликовать можно только активную технику с полной матрицей из 15 тарифов;
- тип категории должен совпадать с типом техники, если тип категории задан;
- деактивация категории автоматически скрывает назначенную ей технику;
- изменение каталога и видимости записывается в `audit_logs`.

Каталог фильтруется по поисковой строке, типу, категории, active-state, видимости и
полноте тарифов. На экране отдельно показаны счетчики общего количества, активной и
опубликованной техники, а также техники с неполным прайсом.

## 3. Фотографии

Для одной единицы техники можно загрузить несколько `jpg/jpeg/png/webp`, изменить
порядок, назначить primary photo и удалить отдельное фото. Первое загруженное фото
становится primary автоматически.

Оригиналы хранятся на Laravel `public` disk. Для каждого файла backend генерирует
центрально кадрированный WebP thumbnail `480x320` с качеством 82. Presenter отдает URL
оригинала и thumbnail; эти же данные будут использованы Bot API на этапе 8.

Максимальный размер задается `VEHICLE_PHOTO_MAX_MB`, по умолчанию 8 MB. Ошибка БД или
аудита откатывает запись и удаляет уже созданные файлы, поэтому orphan-файлы после
неуспешной загрузки не остаются. Операции одного транспортного средства блокируют его
строку на время транзакции, поэтому параллельные upload/arrange/delete не создают две
primary-фотографии или противоречивый порядок.

## 4. Редактор цен

Редактор показывает единую матрицу `3 сезона x 5 тарифных уровней`:

- сезоны `low`, `middle`, `high`;
- уровни `1d`, `7d`, `14d`, `21d`, `month`.

Администратор вводит итоговую сумму каждого уровня. Backend сохраняет сумму и заново
вычисляет дневную ставку через decimal arithmetic. Сумма должна быть положительной:
нулевая цена не считается заполненным тарифом. Любой отсутствующий или
выключенный элемент делает прайс неполным и автоматически скрывает технику для
клиентского бронирования. Полная матрица заменяется под row lock техники, поэтому два
параллельных сохранения не могут оставить смешанный набор тарифов.

Контрольный preview принимает даты и использует тот же `PriceCalculator`, который
используется при создании брони: тарифный уровень выбирается по общей длительности,
дни раскладываются по сезонам, итог округляется до 100 THB. Отдельной формулы во
frontend нет.

## 5. Клиенты и документы

Список клиентов поддерживает поиск по имени, телефону, email и Telegram identity.
Карточка показывает все контакты, историю бронирований и переход к ручному созданию
брони с уже выбранным клиентом.

Документы можно привязать к клиенту либо к конкретной брони. Поддержаны типы
`passport`, `driver_license`, `photo`, `other` и файлы `pdf/jpg/jpeg/png/webp`.
Максимальный размер задается `CUSTOMER_DOCUMENT_MAX_MB`, по умолчанию 10 MB.

Документы хранятся на отдельном `private` disk без публичного URL. Загрузка,
скачивание и удаление проходят только через controller под `auth + verified`.
Физическое удаление выполняется после успешного commit; при ошибке аудита новая
запись и файл откатываются согласованно.

## 6. CSV бронирований

Экспорт использует тот же серверный query и те же фильтры/сортировку, что таблица
бронирований. Данные читаются порциями по 500 строк, поэтому весь набор не загружается
в память.

Файл формируется с UTF-8 BOM и разделителем `;` по умолчанию. Разделитель можно
изменить через `BOOKING_CSV_DELIMITER`. Значения, начинающиеся с `=`, `+`, `-` или `@`,
экранируются для защиты от spreadsheet formula injection. Формат проверен
автоматическими тестами на совместимость с Excel/Google Sheets по кодировке и
разделителю.

## 7. Интерфейс

В боковую навигацию добавлены `Fleet` и `Customers`. Реализованы:

- desktop-таблицы и отдельные компактные mobile layouts;
- серверная пагинация и фильтры;
- форма техники с вкладками `Details`, `Photos`, `Pricing`;
- модальное создание/редактирование категории;
- управление primary photo и порядком;
- индикатор `15/15` и явное предупреждение о неполном прайсе;
- карточка клиента с контактами, документами и историей;
- CSV-кнопка, сохраняющая текущие фильтры таблицы бронирований.

Browser QA выполнен на `1440x1000` и `390x844`. Горизонтального переполнения страницы,
пересечений элементов и runtime/page errors не обнаружено.

## 9. Требования к окружению

Перед показом публичных фото нужно выполнить:

```powershell
cd backend
php artisan storage:link
```

На сервере обязательны PHP GD с поддержкой WebP и права записи на
`backend/storage/app/public`, `backend/storage/app/private` и
`backend/storage/framework`. Private storage нельзя публиковать через web-server.
